## How to rerun

- **Workflow test:** `npx playwright test tests/e2e/integration.spec.ts` (part of `npm run test:e2e`).
- **Second dev server:** `playwright.config.ts` reads `E2E_PORT` (default 3000), so a QA run can use its own server, for example `E2E_PORT=3101 npx playwright test`.
- **Upgrade chain** (not part of `npm run test:e2e`):
  1. Make detached checkouts of `8b0c32c`, `d6a0268` and `8551473` (`git worktree add --detach <dir> <sha>`), and run `npm ci` and `npm run build` in each. Do the same for a schema 4 build (this branch or `359fa76`).
  2. With port 3000 free, run (Git Bash): `WT_V01=<dir> WT_BT=<dir> WT_CP=<dir> WT_BM=<dir> CHAIN_OUT=<empty dir> bash tests/upgrade-chain/run-chain.sh`.
  3. The script serves each build with `next start -p 3000` and runs one phase of `tests/upgrade-chain/chain.spec.ts` in one persistent Chromium profile. It stops each server by port, because Git Bash `kill` leaves the Windows node child running.
  4. Dumps of every IndexedDB store before and after each upgrade, the backups made on the way, and the logs land in `CHAIN_OUT`.

## Findings

Severity follows the vault Code Review skill. There are no Critical findings. The High findings were fixed in the first QA commit. At the owner's request, the Medium findings were fixed in a second commit. The Low findings are recorded for the owner.

### Fixed (High)

- **H-1 A batch's production date could move past its burn tests.**
  - Trigger: record a burn test on a batch, then edit the batch and set a later production date. The batch form and `batches.update` accepted it.
  - Impact: the burn test was dated before its batch was made, which breaks the BurnMatrix rule. The test could not be edited until the maker changed its date, and the screen only showed a generic save failure. The data layer also accepted a burn test dated before its batch from any caller other than the editor.
  - Fix:
    - `batches.update` refuses a production date later than the earliest burn test.
    - `burnSessions.create` and `update` refuse a test date before the production date.
    - The batch form shows "A burn test on this batch is dated …. The production date can't be later than that."
  - Tests: `tests/unit/db/integration-dates.test.ts`, `tests/unit/batches/form-model.test.ts`, a component test in `tests/unit/batches/batches.test.tsx`, and an e2e step in `tests/e2e/burn.spec.ts`.
- **H-2 No visible keyboard focus on buttons, inputs, selects and textareas.**
  - The cause dates from v0.1: Tailwind 4's `outline-none` is `outline-style: none` in the utilities layer, which beats the one global `:focus-visible` outline (PRD-29) in the base layer. Only plain links showed focus.
  - Fix: `outline-none` is removed from focusable controls (`button`, `input`, `textarea`, and the field classes of the session, material and cure-plan editors). The stretched row links in the batch and formula lists lose it too.
  - Test: `tests/e2e/focus.spec.ts`.

### Fixed (test reliability)

- `shell.spec.ts` "formula routes": on an empty home page there are two "New formula" links (header and empty state). It now clicks the header link.
- `shell.spec.ts` keyboard focus: a nav link focused before hydration is replaced when the Suspense fallback swaps, which drops focus. The test now waits for the page to hydrate first. The app side is recorded as L-3.

### Fixed (Medium), at the owner's request after the first QA commit

The first QA commit recorded these seven findings without fixing them. The owner then asked for them to be fixed on this branch.

- **M-1: two burn tests linked to one planned burn test after a merge restore.**
  - Cause: two devices share a cure plan through a restore, and each links its own session.
  - Effect before the fix: editing either session failed with the generic save error until one was unlinked.
  - Decision: a restore still never refuses a file over this soft link.
  - Fix:
    - `burnSessions.update` keeps a link the session already had. Only a new link must be free.
    - The editor's planned-test picker keeps the session's own link enabled (`isPlannedTestTaken`).
    - The restore preview says how many planned burn tests will be linked more than once (`RestorePlan.burnChecks.sharedPlannedTests`).
  - Saving either session marks the planned test done on that session's date, so the last save wins.
- **M-2: a restore did not check the burn-test-date rule.**
  - Cause: a merge could add sessions dated before a batch on the device, and "use the backup's copy" could move a batch's date past the device's sessions. Files from older app versions could also hold such records.
  - Decision: a restore still never refuses a file over this.
  - Fix:
    - A date that is already stored is accepted as it is, in the data layer (`batches.update`, `burnSessions.update`) and in both editors. Other edits of such a record still save. Only a new or changed date must follow the rule.
    - The restore preview says how many burn tests will be dated before their batch (`burnChecks.datesBeforeBatch`).
- **M-3:** the CSV column is now "Maker's conclusion".
- **M-4:** the Replace warning now names every kind of record it removes: formulas, versions, materials, measurements, batches, cure plans, planned production entries, burn tests and burn test photos.
- **M-5:** the broad judgement-word scan now covers `batches`, `schedule` and `backup` too. It has a five-entry allowlist of exact app-operation phrases, such as "Restore finished." and "safety backup". The scan fails if an allowlist entry stops matching.
- **M-6:** the shared `DialogContent` remembers what had focus when it opened and returns focus there on close, unless the opener is gone. The photo delete confirmation focuses "Keep photo" first (this also fixes L-11).
- **M-7:** after Remove milestone, Remove candle or Remove burn, focus moves to the row that took its place, or the previous row, or the section's Add button (`src/lib/focus-after-remove.ts`).
- **Tests:**
  - `tests/unit/db/integration-dates.test.ts` (M-1, M-2) and `tests/unit/backup/burn-checks.test.ts`.
  - Form-model and preview tests in `tests/unit/batches`, `tests/unit/burn-ui` and `tests/unit/backup-page`.
  - The extended scan in `tests/unit/messages/messages.test.ts`.
  - `tests/e2e/focus-return.spec.ts`. Remove candle and Remove burn share the M-7 helper but have no test of their own.
