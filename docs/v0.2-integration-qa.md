## How to rerun

- **Workflow test:** `npx playwright test tests/e2e/integration.spec.ts` (part of `npm run test:e2e`).
- **Second dev server:** `playwright.config.ts` reads `E2E_PORT` (default 3000), so a QA run can use its own server, for example `E2E_PORT=3101 npx playwright test`.
- **Upgrade chain** (not part of `npm run test:e2e`):
  1. Make detached checkouts of `8b0c32c`, `d6a0268` and `8551473` (`git worktree add --detach <dir> <sha>`), and run `npm ci` and `npm run build` in each. Do the same for a schema 4 build (this branch or `359fa76`).
  2. With port 3000 free, run (Git Bash): `WT_V01=<dir> WT_BT=<dir> WT_CP=<dir> WT_BM=<dir> CHAIN_OUT=<empty dir> bash tests/upgrade-chain/run-chain.sh`.
  3. The script serves each build with `next start -p 3000` and runs one phase of `tests/upgrade-chain/chain.spec.ts` in one persistent Chromium profile. It stops each server by port, because Git Bash `kill` leaves the Windows node child running.
  4. Dumps of every IndexedDB store before and after each upgrade, the backups made on the way, and the logs land in `CHAIN_OUT`.

## Findings

Severity follows the vault Code Review skill. Critical and High findings are fixed here. Medium and Low findings are recorded for the owner. No Critical findings.

### Fixed (High)

- **H-1 A batch's production date could move past its burn tests.**
  - Trigger: record a burn test on a batch, then edit the batch and set a later production date. The batch form and `batches.update` accepted it.
  - Impact: the burn test was dated before its batch was made, which breaks the BurnMatrix rule. The test could not be edited until the maker changed its date, and the screen only showed a generic save failure. The data layer also accepted a burn test dated before its batch from any caller other than the editor.
  - Fix:
    - `batches.update` refuses a production date later than the earliest burn test.
    - `burnSessions.create` and `update` refuse a test date before the production date.
    - The batch form shows "A burn test on this batch is dated …. The production date can't be later than that."
  - Tests: `tests/unit/db/integration-dates.test.ts`, `tests/unit/batches/form-model.test.ts`, a component test in `tests/unit/batches/batches.test.tsx`, and an e2e step in `tests/e2e/burn.spec.ts`.
- **H-2 No visible keyboard focus on buttons, inputs, selects and textareas.**
  - The cause dates from v0.1: Tailwind 4's `outline-none` is `outline-style: none` in the utilities layer, which beats the one global `:focus-visible` outline (PRD-29) in the base layer. Only plain links showed focus.
  - Fix: `outline-none` is removed from focusable controls (`button`, `input`, `textarea`, and the field classes of the session, material and cure-plan editors). The stretched row links in the batch and formula lists lose it too.
  - Test: `tests/e2e/focus.spec.ts`.

### Fixed (test reliability)

- `shell.spec.ts` "formula routes": on an empty home page there are two "New formula" links (header and empty state). It now clicks the header link.
- `shell.spec.ts` keyboard focus: a nav link focused before hydration is replaced when the Suspense fallback swaps, which drops focus. The test now waits for the page to hydrate first. The app side is recorded as L-3.

### Recorded (Medium)

- **M-1:** A merge restore can leave two burn tests linked to one planned burn test. This happens when two devices share a cure plan through a restore and each links its own session. Editing either session then fails with the generic save error until one is unlinked. The restore check does not test link uniqueness.
- **M-2:** A restore does not check the burn-test-date rule.
  - A merge can add sessions dated before a batch on the device.
  - "Use the backup's copy" can move a batch's production date past the device's sessions.
  - Since H-1, editing such a record shows the new refusal until the date is fixed.
- **M-3:** The CSV column is a bare "Conclusion", so it leaves the app without saying it is the maker's own words. Suggested: "Maker's conclusion".
- **M-4:** `backup.replaceWarning` lists formulas, versions, materials, measurements and batches. It leaves out cure plans, planned production, burn tests and photos. The confirmation dialog's counts are complete, and a safety backup downloads first.
- **M-5:** The broad verdict-word scan in `tests/unit/messages/messages.test.ts` covers only the burn sections. Batches, schedule and backup get only the narrow scan.
- **M-6:** Dialogs (photo view, photo delete, burn test delete) do not return focus to their opener after Escape or Cancel. Focus lands on `body`.
- **M-7:** After removing a milestone, candle or burn row, focus lands on `body`.

### Recorded (Low)

- **L-1:** Orphan-check gaps that only a hand-edited file with a valid checksum can reach:
  - A batch whose version is only on the device is not checked against the batch's formula.
  - A planned entry's device batch is not checked against the entry's version.
  - Two planned entries can name the same batch.
- **L-2:** A linked planned burn test can be marked not done while its session stays linked. The schedule then lists it as due, and the next save of the session marks it done again.
- **L-3:** A keyboard user who focuses a nav link before hydration loses focus when the Suspense fallback is replaced (`src/components/shell/nav.tsx`).
- **L-4:** The verdict-word lists miss words such as complete, finished, success, ideal, optimal, perfect, better, worse, rating and verified.
- **L-5:** "Done on" uses the success colour next to "Planned cure end", which could read as "cure complete".
- **L-6:** "Cure time: N days" could read as a recommendation. Suggested: "Planned cure time".
- **L-7:** The soot name is "None seen" in some places and "None" in others.
- **L-8:** Two dialogs' screen-reader descriptions repeat their titles (`delete-dialog.tsx`, `photo-section.tsx`).
- **L-9:** After Add, focus stays on the Add button. In the cure-plan editor the new row is above it.
- **L-10:** After a save that navigates, focus is on `body`.
- **L-11:** The photo delete confirmation focuses its container, not a button.
- **L-12:** Two schedule rows can share one accessible link name.
