# v0.3 TrueCandle Cost — design and implementation plan

2026-11-29. Lead design for the TrueCandle Cost slice (`docs/BUILD-STATE.md`, vault `Projects/apps/candle/Tasks.md`
v0.3). Branch `feat/v0.3-cost` from `feat/v0.3-candlefix` (`ac75476`); its PR merges into that branch. The owner
approved the plan and its defaults before this note was written; it records them and fills in the details.

TrueCandle Cost turns a saved formula version or a recorded batch into a **cost sheet**: materials, packaging and other
items, labour, overhead and a testing allowance, spread over the candles that can be sold. It shows the **cost per
sellable candle** in PHP and a **wholesale** and a **retail** pricing scenario with profit per candle and gross margin.

## Principles

1. **Money is whole centavos.** Every stored amount is an integer number of centavos (`…Centavos`), PHP only. There is
   no currency field and no exchange rate.
2. **Exact until shown.** The calculator never rounds. Amounts that come out fractional (a weight times a per-kg price, a
   share of a batch) are kept as exact fractions and rounded **half up** (half away from zero for a negative profit) to
   the centavo only when shown. A total is the exact sum, rounded once, so shown lines can differ from a shown total by a
   centavo; the results say so in one line.
3. **A sheet is a snapshot.** Creating a sheet copies the quantities and unit prices it uses. Editing a material's
   default price, a lot's purchase price, a packaging item or the batch later never changes a saved sheet. **Copy and
   update** makes a new sheet from current data; the old one stays as it was.
4. **Every cost line says where its price came from:** the batch's lot, the material's default price, a price typed on
   this sheet, or "No price".
5. **No tax advice.** The app assumes the maker is not VAT-registered, so every cost is recorded as paid. A "Prices
   include 12% VAT" switch on the scenarios is off by default. Nothing in the app says a price is right, fair or
   profitable enough; it shows the arithmetic.

## Data model (schema 7)

Types in `src/lib/types.ts` (TrueCandle Cost section); schemas in `src/lib/schemas/cost.ts`.

### Prices on materials and lots

```ts
// Material gains (optional, absent on every older record):
defaultPriceCentavos?: number;   // 0–MAX_MONEY_CENTAVOS. Per kg for wax and fragrance oil, per piece for wicks and vessels.

// MaterialLot gains (optional):
purchase?: {
  paidCentavos: number;          // 0–MAX_MONEY_CENTAVOS, what the maker paid for the lot as received
  quantity: number;              // what was received: milligrams (1–LIMITS.maxWeightMg) for wax and oils,
};                               // pieces (1–MAX_LOT_PIECES) for wicks and vessels
```

The price unit follows the material type (`priceUnitOf(type)`: `"kg"` for wax and fragranceOil, `"piece"` for wick and
vessel), so no record stores a unit that could disagree with its type. A lot's quantity is checked against its material's
type by the data layer (the lot schema alone does not know the type). The screens take kilograms or grams for weights
(stored as milligrams) and whole pieces.

### Candle counts on batches

```ts
// Batch gains (optional):
candlesMade?: number;   // 1–MAX_CANDLES (100 000)
sellable?: number;      // 0–candlesMade; present only when candlesMade is
```

`sellable ≤ candlesMade` is a schema rule. `BatchInput` gains `candlesMade?: number | null` and `sellable?: number |
null`: absent keeps what is stored (as `lots` does), `null` clears it. Clearing `candlesMade` while `sellable` stays is
`invalid`. The batch form shows "Candles made" and "Sellable" as optional whole-number fields; the batch page shows them
when recorded.

### Packaging and other items (store `costItems`)

```ts
CostItem = {
  id: uuid;
  name: string;             // 1–60 after trimming, unique (case-insensitive, archived included)
  unitCentavos: number;     // 0–MAX_MONEY_CENTAVOS, price of one
  notes?: string;           // ≤ 2000
  archivedAt: timestamp | null;   // archived items are hidden from the sheet's picker
  createdAt; updatedAt;
}
```

A small list on its own screen (`/materials/items`, reached from the material library like Lots and Suppliers).

### Cost sheets (store `costSheets`)

```ts
CostSheet = {
  id: uuid;
  title?: string;                 // 1–60 after trimming
  basis: "version" | "batch";     // fixed at creation
  formulaId: uuid;                // fixed; the version's formula
  versionId: uuid;                // fixed; for a batch sheet, the batch's version
  batchId: uuid | null;           // fixed; set exactly when basis is "batch"
  candlesMade: number;            // 1–MAX_CANDLES
  sellable: number;               // 0–candlesMade
  materials: CostMaterialLine[];  // one per component of the version, in the version's order; unique key
  items: CostItemLine[];          // 0–MAX_SHEET_ITEMS (30), unique id
  labourHoursX100: number;        // hundredths of an hour, 0–100 000 (1 000 h)
  labourRateCentavos: number;     // per hour, 0–MAX_MONEY_CENTAVOS
  overhead: { mode: "fixed"; centavos: number }        // per batch, 0–MAX_MONEY_CENTAVOS
          | { mode: "percent"; bp: number };           // of materials + labour, hundredths of 1 %, 0–100 000
  testingCentavos: number;        // testing allowance per batch, 0–MAX_MONEY_CENTAVOS
  pricesIncludeVat: boolean;      // default false
  wholesale: CostScenario | null; // null = not set
  retail: CostScenario | null;
  copiedFromId: uuid | null;      // soft link to the sheet this was copied from
  notes?: string;                 // ≤ 2000
  createdAt; updatedAt;
}

CostMaterialLine = {
  key: string;                    // batchLotSlot form: "row:<componentId>", "wick" or "vessel"
  materialId: uuid;               // the component's material (snapshot of the link)
  materialType: MaterialType;
  name: string;                   // the material's name in the version snapshot
  quantity: { unit: "mg"; mg: number; from: "planned" | "measured" }   // wax and oil rows, per batch
          | { unit: "piece"; perCandle: number };                       // wick and vessel, 0–50 per candle made
  price: CostPrice;
}

CostPrice =
  | { source: "lot"; lotId: uuid; lotCode: string; paidCentavos: number; quantity: number }
  | { source: "material"; unitCentavos: number }   // per kg or per piece, copied from the material
  | { source: "sheet"; unitCentavos: number }      // typed on this sheet, per kg or per piece
  | { source: "none" };                            // no price known: the line counts as ₱0 and the sheet is marked incomplete

CostItemLine = {
  id: uuid;                       // the line's own id
  itemId: uuid | null;            // soft link to the costItems entry it was picked from, or null for a one-off
  name: string;                   // 1–60, snapshot
  unitCentavos: number;           // snapshot, editable on the sheet
  per: "sellable" | "batch";      // each sellable candle, or once for the batch
  quantity: number;               // 1–1 000
}

CostScenario = { mode: "price"; priceCentavos: number }   // 1–MAX_MONEY_CENTAVOS
             | { mode: "margin"; marginBp: number };       // target gross margin, 0–9 999 (99.99 %)
```

`MAX_MONEY_CENTAVOS` is 1 000 000 000 (₱10,000,000.00). `MAX_LOT_PIECES` is 1 000 000.

Why the quantities are copied rather than read live: a batch's measured weights can still be edited, and the sheet must
keep the numbers it was costed with. Version targets never change, but they are copied too so every sheet reads the same
way.

## Building a sheet (snapshot rules)

`costSheets.create` builds the lines inside its transaction from the data as it is at that moment:

| Component | Quantity | Price (first that applies) |
| --- | --- | --- |
| Wax or oil row, **version** sheet | the version's planned weight (`targets`), `from: "planned"` | the material's default price → none |
| Wax or oil row, **batch** sheet | the batch's measured weight; a row not measured uses the planned weight, `from: "planned"`, and the screen says "Planned (not measured)" | the batch's lot on that row, if it has a purchase price → the material's default price → none |
| Wick, vessel | 1 per candle made (editable 0–50 on the sheet) | the batch's lot on that part (batch sheets), if priced → the material's default price → none |

"The material's default price" reads the material record as it is now (not the version's snapshot, which has no price).
An archived material's price still counts. A lot snapshot keeps the lot's id, code, amount paid and quantity received.

Candle counts: a version sheet needs "Candles made" from the maker (the form suggests the vessel count when the
version was sized by vessels). A batch sheet takes the batch's counts when recorded; otherwise the form asks for them.
"Sellable" defaults to "Candles made".

**Editing a saved sheet** may change: the title, notes, candle counts, pieces per candle on wick and vessel lines, a
line's price (only to a price typed on this sheet, or to no price; any other change is `invalid`), the items, labour,
overhead, testing allowance, the VAT switch and the scenarios. The basis, formula, version, batch, line keys,
materials and weights never change.

**Copy and update** (`costSheets.copy`) writes a new sheet with the same basis, title ("copy" is not added; the maker
renames it), candle counts, items, labour, overhead, testing, VAT switch, scenarios and notes, and `copiedFromId` set.
Then it refreshes:
- quantities: the version's targets, or the batch's current measured weights;
- candle counts: the batch's counts when the batch records them, otherwise the old sheet's;
- prices: lot → material → none as above, **except** a line whose price was typed on the old sheet keeps that typed
  price (the maker chose it for this costing);
- item lines picked from the list take the item's current unit price when the item still exists; one-off lines and
  lines whose item was deleted keep theirs.

## The calculation (`src/lib/cost`, pure)

All amounts are exact fractions (`bigint` numerator and denominator). Weights in mg, prices in centavos.

```
material line (mg, lot)       = mg × paidCentavos ÷ lotQuantityMg
material line (mg, per kg)    = mg × unitCentavos ÷ 1 000 000
material line (piece, lot)    = perCandle × candlesMade × paidCentavos ÷ lotQuantityPieces
material line (piece, price)  = perCandle × candlesMade × unitCentavos
material line (none)          = 0, counted in `missingPrices`
materials                     = Σ material lines
item line                     = unitCentavos × quantity × (sellable if per "sellable", 1 if per "batch")
items per batch               = Σ item lines per "batch"
packaging                     = Σ item lines per "sellable"          (already × sellable)
labour                        = labourHoursX100 × labourRateCentavos ÷ 100
overhead                      = fixed centavos, or (materials + labour) × bp ÷ 10 000
production                    = materials + items per batch + labour + overhead
cost per candle made          = production ÷ candlesMade
non-sellable candles          = candlesMade − sellable
cost of non-sellable candles  = cost per candle made × non-sellable candles
testing                       = testingCentavos
batch total                   = production + testing + packaging
cost per sellable candle      = batch total ÷ sellable                (none when sellable is 0)
  of which production         = production ÷ sellable  (includes the non-sellable share)
  of which non-sellable share = cost of non-sellable candles ÷ sellable
  of which testing            = testing ÷ sellable
  of which packaging          = packaging ÷ sellable
```

Failed candles are therefore paid for by the sellable ones: their materials, labour and overhead are in `production`
and divided by `sellable`, not by `candlesMade`. Packaging per sellable candle is never charged for a failed candle.

### Scenarios, margins and VAT

Let `C` be the cost per sellable candle and `v` = 1.12 when "Prices include 12% VAT" is on, 1 when off.

| Set by | Price shown (`P`) | Price without VAT (`E`) |
| --- | --- | --- |
| Price | the price typed | `P ÷ v` |
| Target margin `m` (0 ≤ m < 100 %) | `E × v` | `C ÷ (1 − m)` |

Then `VAT in the price = P − E` (shown only when the switch is on), `profit per candle = E − C`, `gross margin = (E −
C) ÷ E`, and `profit for the batch = profit per candle × sellable`. With VAT on, margin is always worked out on the
ex-VAT price. A margin target of 100 % or more is refused (field error; the calculator also returns
`margin-unreachable`). No scenario is worked out when there are no sellable candles (`no-sellable`). A typed price must
be at least ₱0.01. A negative profit or margin is shown with a minus sign, never coloured as good or bad.

Display: `₱1,234.56` (two decimals, thousands commas, ASCII hyphen-minus for negatives, e.g. `-₱12.30`). Margins as a
percentage with two decimals (`51.98%`), from the exact fraction rounded half up. Per-kg prices read "₱1,850.00 per kg";
per-piece prices "₱38.50 each".

## Repositories (`@/lib/db`)

| Repo | Operations |
| --- | --- |
| `costItems` | `list({includeArchived})` by name, `get`, `create`, `update`, `setArchived`, `usage(id)` → `{ sheets }` (sheets with a line picked from it), `delete` (allowed while sheets use it: they keep their copy; the confirmation says how many) |
| `costSheets` | `list({ formulaId?, batchId? })` → items with formula, version and batch (null for version sheets), newest first; `get(id)` → detail with the same plus `copiedFrom` (or null); `create(request)` idempotent by `sheetId`; `update(id, input)`; `copy({ sheetId, fromId })` idempotent by `sheetId`; `delete(id)`. | `materials` | input and record gain `defaultPriceCentavos` |
| `materialLots` | input and record gain `purchase`; "invalid" when the quantity is outside the range for the material's type |
| `batches` | input and record gain `candlesMade` and `sellable` (absent keeps, null clears) |

Write rules (each a `DataError`): `invalid` for a bad field, sellable above candles made, a version sheet without
candle counts, a batch sheet whose batch has no counts and none were given, a line price changed to anything but a
typed price or no price, a changed line key set; `not-found` for a missing version, batch, sheet or (on a new item line)
item. Every write bumps `changesSinceBackup` once.

## Archive and delete rules

| Record | Rule |
| --- | --- |
| Batch | Delete refused (`in-use`) while a cost sheet is based on it. `deletionImpact` adds `costSheets`. Editing the batch never changes its sheets. |
| Formula | Permanent delete refused (`in-use`) while a cost sheet is based on any of its versions. `deletionImpact` adds `costSheets`. Archiving changes nothing. |
| Formula version | Write-once and only deleted with its formula (above). |
| Material | Never deleted (as before). Editing its default price never changes a saved sheet. |
| Lot | Unchanged rules (archive when a batch links it). A sheet's lot price is a snapshot: deleting or editing the lot leaves the sheet as it was; the line still names the lot code. |
| Packaging item | Can be archived (hidden from the picker) or deleted; sheets keep their copies. |
| Cost sheet | Deleted alone after confirmation. Nothing else changes; a sheet copied from it keeps `copiedFromId` (soft) and reads "Copied from a sheet that was deleted". |

## Backup format 7

- `DATA_STORES` gains `costItems` and `costSheets` (appended). `BACKUP_FORMAT_VERSION` 7.
- `checkBackupText` reads formats 1 to 7: each format is checked against its own shape and checksum, then the stores it
  lacks are added empty. Older formats are checked with their own record shapes, so a format 6 file whose material has
  a price, whose lot has a purchase, or whose batch has candle counts is refused as damaged (`MaterialSchemaV1`,
  `MaterialLotSchemaV5`, `BatchSchemaV5`, as `BatchSchemaV2` was for lots).
- Orphan counting adds `costSheets` (version or batch not in the file or on the device).
- `planRestore`: both stores are editable records classified whole (`canonicalJson`).
- **Integrity (`integrity.ts`), new required links:**
  - cost sheet → its version (`version-missing`), which belongs to the sheet's formula (`version-of-other-formula`);
  - batch cost sheet → its batch (`batch-missing`), made from the sheet's version (`batch-of-other-version`);
  - each material line → a component of that version (`component-missing`) whose material is the line's material
    (`line-of-other-material`).
  Replace needs them in the file; Merge may use the device's records.
- **Soft, unchecked:** a line's lot id (the price is a snapshot), an item line's item id, `copiedFromId`.

  was; Copy and update picks them up in a new sheet.
